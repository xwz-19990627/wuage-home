# wuage-home · 已定决策（记录于 2026-08，随讨论更新）

> 原则：**先跑通，再迁移**。每个决策都留好迁移口子。

## 1. 运行环境

- **现状**：跑在本机（即当前 DSH 所在的这台机器）。
- **要求**：可迁移。代码与数据分离、配置外置、不依赖特定机器状态。
- **落地**：
  - 代码仓库只含代码 + 配置模板（`config.example.yaml`），不落运行时数据。
  - 数据目录由环境变量 `WUAGE_DATA` 指定，默认 `<repo>/data`。
  - 迁移 = 拷贝 `WUAGE_DATA` 目录 + 重装依赖 + 改配置。后续可 Docker 化，或搬到 NAS。

## 2. 交互入口（MVP 做最简单的）

- **最终形态**：Web / App / 微信 / QQ 都想做。
- **MVP**：本机 **Web 页面**（浏览器即可用，同局域网手机可访问，无需审核/上架）。
- **架构预留**：交互层做成适配器（Web 入口、后续 Telegram/微信/QQ/App 入口），内核不感知入口。
- 微信/QQ 需要官方机器人审核或非官方协议（有封号风险），留到第二阶段再评估。

## 3. 数据存储

- **MVP**：磁盘文件 + SQLite，本地优先。
- **固定位置**：所有数据统一放 `WUAGE_DATA`（默认 `./data`），布局文档化：
  - `data/ledger.db` — 账本
  - `data/journal/` — 家庭日志/文本
  - `data/news/` — 订阅与简报缓存
  - `data/config.yaml` — 运行时配置（密钥等）
- **未来**：家庭 NAS 就位后，把存储层换成 NAS 挂载点 / 数据库，模块接口不变。

## 4. 模型

- 依赖 **DeepSeek V4 Flash**（OpenAI 兼容 API）承担理解/结构化/生成。
- V4 Flash 定位：强能力 + 低成本 + 快 → 适合高频家庭场景（记账解析、日报生成、问答）。
- 模型名/API 以 DeepSeek 官方文档为准，代码中集中配置，方便切换。
