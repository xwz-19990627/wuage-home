# wuage-home · 已定决策（记录于 2026-08，随讨论更新）

> 原则：**先跑通，再迁移**。每个决策都留好迁移口子。

## 1. 运行环境

- **现状**：跑在本机（即当前 DSH 所在的这台机器）。
- **要求**：可迁移。代码与数据分离、配置外置、不依赖特定机器状态。
- **落地**：
  - 代码仓库只含代码 + 配置模板（`config.example.yaml`），不落运行时数据。
  - 数据目录由环境变量 `WUAGE_DATA` 指定，当前 `/root/wuage/data`（2026-08-23 起数据根 `$WUAGE_HOME`=/root/wuage 与代码仓库分离，迁移拷整体）。
  - 迁移 = 拷贝数据根 + 重装依赖 + 改配置。后续可 Docker 化，或搬到 NAS。

## 2. 交互入口（MVP 做最简单的）

- **最终形态**：Web / App / 微信 / QQ 都想做。
- **MVP**：本机 **Web 页面**（浏览器即可用，同局域网手机可访问，无需审核/上架）。
- **架构预留**：交互层做成适配器（Web 入口、后续 Telegram/微信/QQ/App 入口），内核不感知入口。
- 微信/QQ 需要官方机器人审核或非官方协议（有封号风险），留到第二阶段再评估。

## 3. 数据存储

- **MVP**：磁盘文件 + SQLite，本地优先。
- **固定位置**：所有数据统一放 `$WUAGE_HOME/data`（当前 /root/wuage/data），布局文档化：
  - `data/ledger.db` — 账本（记账模块）
  - `data/memory.db` — 家庭记忆（规划：facts 表 + FTS5）
  - `data/toolbox/files/` — 工具箱文件（互传/导入）
  - `data/backups/` — 每日备份（保留 7 份）
  - 新模块数据一律落 data/ 下命名空间，禁止散落仓库根目录
- **未来**：家庭 NAS 就位后，把存储层换成 NAS 挂载点 / 数据库，模块接口不变。

## 4. 模型

- 依赖 **DeepSeek V4 Flash**（OpenAI 兼容 API）承担理解/结构化/生成。
- V4 Flash 定位：强能力 + 低成本 + 快 → 适合高频家庭场景（记账解析、日报生成、问答）。
- 模型名/API 以 DeepSeek 官方文档为准，代码中集中配置，方便切换。

## 5. 知识库与工作流（架构立场）

- **记忆分两层**：
  - 事实层（结构化）：账本、日期、决定、实体/关系 —— SQLite 起步，这是家庭记忆的主干。
  - 文档层（非结构化）：日志、PDF、票据、聊天记录 —— 起步用 SQLite FTS5 全文检索 + LLM 语义兜底；不提前上向量库。
- **不搭通用工作流引擎**（n8n/Dify 这类是平台陷阱，等于重建别人做好的东西，且与家庭规模不匹配）。**“流程即代码”**：每个模块内部声明自己的流水线（触发器：指令/定时/事件 → 步骤：取数→LLM→输出），由内核调用，代码可调试、可测试。
- **升级阈值（不预支）**：文档量或流程复杂度真到了撑不住的那天，再把记忆升到向量库、把流程抽成引擎。预留好接口（事实库 + 技能卡），升级只换实现不换形态。

## 6. 内核决策：不开发 agent 内核，复用 DSH 壳子

- **问题**：这算是在开发 agent 吗？内核要不要从零写？
- **结论**：不是开发 agent 内核，而是开发"家庭智能体应用"。内核（agent 循环、工具执行、GUI、调度）直接用本机 DSH，不重复造轮子。
- **分工**：
  - DSH 提供：指令路由（LLM）、工具执行、Web 界面入口、定时调度（任务看板/cron）、多 agent。
  - wuage-home 负责（差异化所在）：**家庭记忆库**（SQLite 事实层，归我们所有）、**技能卡/模块**、**主动提醒剧本**、**数据迁移**。
- **为什么成立**：DSH 本身就是"输入指令 → 路由 → 工具 → 结论"的机器，还自带 Web GUI；而家庭智能体的灵魂（多年记忆、主动提醒、私有数据）DSH 默认不提供，正好由我们补上。
- **边界提醒**：
  - DSH 会话不是长期事实记忆 —— 事实必须落在 wuage-home 自己的数据层（WUAGE_DATA），技能卡只做读写该层的入口。
  - DSH 工具有整机权限 —— MVP 入口限定本机/局域网；以后接外网入口（QQ bot）时再评估权限边界和隔离。
  - 可迁移性 = 在目标机器（未来的 NAS）安装 DSH + 拷贝 WUAGE_DATA + 部署技能卡。
- **MVP 形态（比独立服务更小）**：数据层（ledger.db + 读写脚本）+ 记账技能卡（DSH skill/preset）+ 周报脚本；入口 = DSH Web GUI 对话。不再需要 FastAPI 服务与前端。
- **备选路线**：若 DSH 耦合日后成为瓶颈，可过渡到独立 FastAPI 服务（技能卡 → HTTP API 是无痛的替换点）。

### 6.1 中枢形态确认（2026-08-21 讨论）

- 确认 **DSH = 家庭智能体中枢（brain）**，wuage-home = 业务内核（记忆/数据/技能）。
- **否定“纯 API 解析”路线**：能力天花板低（只有解析，没有 agent 循环/工具/多轮/记忆），
  不满足 harness 效果；解析、路由、多轮纠错、叙述都经中枢会话完成。
- 否定自造 harness（LangGraph/Agents SDK）与 n8n/Dify 路线：重建轮子 / 工作流平台非所需。
- 边界：**智能入中枢、事实入 wuage 数据层**；中枢扩展 = preset + skill + 插件 + 任务看板 cron。
- 迁移：安装 DSH + 部署 wuage 仓库 + 拷贝数据根 /root/wuage，整套体系可搬。
