# wuage-home · 最终形态愿景（讨论中）

> 用户口述整理，随讨论演进。这是"北极星"，MVP 不需要一下做到，但每个设计决策都应朝它对齐。

## 用户描述的交互形态

- 入口：可以是 App，也可以是 QQ bot 这类机器人；最终可能多个入口并存。
- 用法：**只输入指令，给结论**；或按指令路由到不同能力做对应的事。
- 疑虑：这"普通 agent 就能干"，担心最终形态太简单。

## 我的判断：路由是骨架，不是灵魂

"指令 → 路由 → 执行 → 结论"的管道确实是通用 agent 的标配（DSH 本身就是）。
让 wuage-home 不普通的，是它作为**家庭的长期成员**区别于"一次性对话 agent"的四件事：

1. **记忆（以年为单位）** — 账本、日志、票据、事实、决定、事件都沉淀成"家庭记忆库"。
   agent 无状态，wuage-home 有历史：能回答"去年端午我们干了什么""今年水电比去年贵了多少"。
2. **主动（proactive，不止被动应答）** — 它持续运行、观察数据，在关键时刻主动开口：
   "本月外卖花费环比 +40%，这周加班多（日历佐证），要不要建两个'备菜日'提醒？"
   最终形态是**被提醒的生活方式管家**，而不是指令执行器。
3. **数据主权（私有 + 可迁移）** — 跑在自己的硬件上（本机 → 未来 NAS），记忆是自家的；
   模型是租的（DeepSeek API），但数据永远是自己拷得走的（WUAGE_DATA 设计）。
4. **多通道（输入输出分离）** — 输入可以是文字/语音/票据照片/短信；输出可以是 App、
   QQ bot、邮件、桌面提醒。入口适配器只换壳，内核不动。

## 可扩展性设计（回应"以后别的模块怎么办"）

- **内核三件套**：路由（LLM 理解指令）+ 记忆库（事实 + 向量检索）+ 模块注册表（工具列表）。
- **每个模块 = 一张"技能卡"**：声明自己 做什么 / 输入 schema / 输出结构 / 数据位置。
  新增功能 = 往注册表加一张卡 + 在 data/ 占好位置，内核自动学会路由到它。
- **模块共享"事实库"而非各建孤岛**：记账模块写入的支出事实，新闻模块可引用、
  周报模块可聚合。这是"1+1>2"的地方，也是架构上最值得认真设计的点。
- **常驻服务 + 触发器**：定时任务 / 事件（如新账单照片）与用户指令走同一套模块调用，
  主动层与被动层共用内核。

## 结论

> **最终形态 = 住在家里的 AI 家庭成员**：常驻内核 + 多年记忆 + 主动提醒 + 私有数据 +
> 多入口（App / QQ bot / Web / 邮件），能力以"技能卡"方式逐年生长。

MVP 的第一块拼图（一句话记账 + 周报）正好是"记忆"的第一个种子：
先让内核有一个可靠的核心记忆（账本），再谈知识库、主动提醒。
